# Adult Income Classification — ML Assignment 2

## a. Problem Statement
Predict whether an individual's annual income exceeds $50,000 based on demographic and employment attributes. This is a binary classification problem (income <=50K or >50K).

## b. Dataset Description
- **Source:** UCI Machine Learning Repository — Adult Income Dataset
- **Features:** 14 input features (age, workclass, fnlwgt, education, education_num, marital_status, occupation, relationship, race, sex, capital_gain, capital_loss, hours_per_week, native_country)
- **Target:** income (binary: 0 = <=50K, 1 = >50K)
- **Instances:** ~48,842 rows (after removing missing values: ~45,222)
- **Task:** Binary Classification

### Observations on Model Performance

| ML Model Name | Observation about model performance |
|---|---|
| Logistic Regression | Achieves solid accuracy (81.7%) and AUC (0.847). However, low recall (0.448) indicates it misses many actual >50K earners, suggesting the linear decision boundary is insufficient for this dataset's complexity. |
| Decision Tree | Best overall performer — highest accuracy (84.8%), AUC (0.893), F1 (0.677), and MCC (0.579). It captures non-linear relationships between income and features like education and occupation effectively. |
| KNN | Moderate performance (82.4% accuracy). KNN is sensitive to the high-dimensional, mixed-type features in this dataset; scaling helps but it still lags behind tree-based models in recall. |
| Naive Bayes | Lowest recall (0.336) and F1 (0.448) among all models. The independence assumption between features is strongly violated here (e.g., education and occupation are correlated), which limits its effectiveness. |
| Support Vector Machine | High precision (0.757) — fewest false positives among all models. Good AUC (0.891) but moderate recall (0.557), suggesting it is conservative in predicting the >50K class. |
| **Overall Winner** | **Decision Tree** — best balance of accuracy, AUC, F1, and MCC on this dataset. |

## e. Preprocessing Methodology

1. **Missing values:** Rows with `?` values dropped (~3,600 rows removed), leaving 45,222 rows.
2. **Train/Test split first:** 80/20 stratified split applied *before* any preprocessing to prevent data leakage.
3. **ColumnTransformer:** `StandardScaler` for 6 numerical features; `OneHotEncoder(handle_unknown='ignore')` for 8 categorical features.
4. **Pipeline:** Each classifier is wrapped in a `sklearn.Pipeline(preprocessor + classifier)` — the entire pipeline is saved as a single `.joblib` file. The Streamlit app loads these pipelines and calls `predict()` on raw feature data; no retraining occurs.
